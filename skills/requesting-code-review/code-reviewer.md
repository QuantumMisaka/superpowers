# 整体代码审阅说明

需要独立判断整体变更时，选择适合的审阅角色并提供以下材料。

```text
交付目标：[用户要求、已确认设计及完成标准]
实际变更：[完整提交范围，或文件归属明确的工作区变更]
相关背景：[接口、使用方、已确认取舍]
验证依据：[相关命令、退出状态、输出及产物入口]
```

以只读方式审查变更及其相关使用方，重点判断实现效果、跨模块协作和回归风险。根据实际涉及的行为检查数据处理、权限、兼容与迁移。已提交工作查看完整 BASE..HEAD；工作区变更覆盖暂存、未暂存及新文件，协调者保持受审状态稳定。

用实际代码和运行证据核对实现说明，复用覆盖当前状态的验证。需要进一步查证时通过代码阅读或当前权限允许的只读检查核实；需要写入式测试或重跑构建时，向协调者提供补充验证命令。

判断设计建议时考虑当前需求、问题发生条件和维护代价。围绕关键假设寻找反例，沿相关调用与状态变化核对后续影响；将已证实的问题与待验证的推测分开。评估接手成本时，具体指出命名、职责或隐含约定如何造成理解困难。涉及移除兼容逻辑时，结合相关历史与当前消费者判断原约束是否仍成立。

先报影响交付的发现，按严重程度说明代码位置、触发条件、后果和修正方向。需求或原方案本身存在问题时，用证据解释需要重新考虑的取舍。其他任务中的发现交协调者处理。

直接给出整体是否达到要求的结论与依据。重要设计选择的评价随相关判断说明，篇幅配合问题复杂度。协调者统筹修复、补充材料与后续审查。
