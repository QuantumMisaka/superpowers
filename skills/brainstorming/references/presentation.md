# 按需呈现设计与计划

当图示、并排比较或长文导航能改善阅读，或用户要求 HTML 时读取本参考。
普通澄清直接在对话中完成；生成视图不触发 SPEC、PLAN 或额外批准。
版式与组件随内容选择，不固定面板数量或章节。

## 源与视图

- 新建 spec / plan 的 Markdown 是唯一可编辑规范源。HTML 是从它生成的阅读视图，注明源路径与“生成视图，修改请回到 Markdown”。
- 意见先合入 Markdown，再重新生成 HTML。阅读视图中的默认选项、未作答和评论本身不代表批准；新增决定按既有协作契约确认。
- 历史 HTML 规范保持有效。实际修订需要迁移时，完整保留决定、验收与来源，更新消费者指针，并把旧文件标为历史版本；不批量转换历史档案。
- 分享与远程镜像沿项目授权；本地渲染不授予上传权限。远程反馈仍须合入本地规范源。

## 使用已有渲染能力

优先复用项目已有工具。`answer-me-with-html` 可作为可选后端：先定位
已安装的 `scripts/am.mjs`，读取该版本帮助，再指定输入与输出，例如：

```bash
node /absolute/path/to/answer-me-with-html/scripts/am.mjs render docs/superpowers/specs/example-design.md -o docs/superpowers/specs/example-design.html --no-open
```

上述路径是使用示例，需要替换为实际路径。工具未安装时，Markdown 仍可直接
交付；需要实际出页再按任务安装或使用现有转换器，不把后端变成工作流前置。
维护者引入后端时记录所用版本，渲染语法以该版本为准。

保留规范中的全部实质内容与链接；需要适配组件语法时，可生成临时输入，
不另存一份独立维护的设计。该后端的 HTML 内嵌源稿和 `am patch` 不取代外部
Markdown：修改回到规范源后重渲染。呈现设置与语言检查随任务调整，不为消除
排版或句长提示改写已定接口、删除论据或压缩必要解释。

生成后检查内容完整、源链接与导航可用，并查看关键图表、宽表格和窄屏布局。
未做视觉检查时如实说明，不以命令成功代替可读性验证。
