# 实现任务说明

选定执行者后，用下面的要素交代本次任务。复用已有需求与计划中的相关内容，按任务需要填写。

```text
目标：[本次需要实现的行为或交付成果]
工作位置与文件分工：[目录、可写文件、同时工作的协作者]
依据：[相关需求、已确认设计、接口与必要上下文]
完成标准：[可观察的结果，已有检查或命令]
```

执行者先查明相关实现，沿用项目设计完成连贯修改，按所需行为验证并自查实际变更。普通技术细节自主确定；需要改变目标、关键设计或文件分工时，把具体选择交给协调者，继续可独立完成的部分。

共享工作区的暂存、提交及生成文件更新由协调者统筹顺序。提交按项目既有工作方式和本次授权执行。需要进一步协作时，执行者向协调者说明工作包与所需帮助，由协调者安排派发和独立审查。

返回结果先说明实现效果，再给相关文件及关键验证结论。命令、退出状态、相关输出和产物应可供核对；已有日志或报告可直接引用。检查应对应交回的实际代码状态，包含本次尚未提交的新文件与修改。采用 TDD 时附相关失败与通过证据。

协调者使用状态标签时，返回 `DONE`、`DONE_WITH_CONCERNS`、`BLOCKED` 或 `NEEDS_CONTEXT`，并说明影响下一步的具体事项。满足完成标准后交回成果。
