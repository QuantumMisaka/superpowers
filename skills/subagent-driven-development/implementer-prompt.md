# 实现任务说明

选定执行者后，按以下四项要素交代工作包，直接复用既有需求与计划中的核心内容，随任务复杂度灵活取舍：

```text
目标：[本轮要实现的可观察行为或交付成果]
工作位置与文件分工：[目标目录、可写文件清单、同期并行的协作者]
依据：[相关需求、已确认设计、接口契约与必要上下文]
完成标准：[可验证的结果、既有检查项或测试命令]
```

**执行与协作约定**：
- 先查明相关实现并顺延项目既有设计完成连贯修改，按目标行为执行验证并自查实际变更。常规技术细节由执行者自主把握；若涉及目标调整、核心设计变更或文件分工冲突，将具体选项提交协调者拍板，同时继续推进可独立完成的部分。
- 共享工作区中的暂存、提交及生成文件更新由协调者统一排定顺序，提交动作遵循项目既有规范与本轮授权。需要额外分工或独立审查时，向协调者说明工作包与诉求，由协调者统筹派发。

**回报要求**：
- 先报实现效果，再列出变更文件与关键验证结论。所附命令、退出码、关键输出与产物入口应便于直接复核（已有日志或报告直接引用），且验证结果严格对应交回时的真实工作区状态（含尚未提交的新增与修改文件）；采用 TDD 时附带关键红绿测试证据。
- 协调者启用状态标签时，按实返回 `DONE`、`DONE_WITH_CONCERNS`、`BLOCKED` 或 `NEEDS_CONTEXT`，并点明影响下一步推进的具体事项，达标后即刻交回成果。
