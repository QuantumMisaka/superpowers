# 单任务审阅说明

任务需要独立审查时，选择适合的审阅角色，提供以下材料。

```text
任务目标与完成标准：[需求、已确认设计或计划中的相关段落]
实际变更：[本次完整提交范围，或文件归属明确的工作区变更]
验证依据：[相关命令、退出状态、输出及产物入口]
需要重点判断的问题：[具体疑点，有则提供]
```

以只读方式对照需求审查实际变更，并查看理解相关行为所需的使用方。已提交工作核对完整 BASE..HEAD；工作区变更同时查看暂存、未暂存及新文件。协调者提供审查期间稳定的工作状态。

将实现报告中的主张与代码、运行结果相互核对。复用覆盖当前变更的有效证据；资料不完整时先回查来源，仍有疑点时通过代码阅读或当前权限允许的只读检查核实；需要写入式测试或重跑构建时，向协调者提供补充验证命令。评价实现方式时依据需求与实际效果，计划中的文件估计帮助定位工作。涉及重要设计取舍时，复用[整体审阅说明](../requesting-code-review/code-reviewer.md)中的判断方法。

先给出影响任务完成的发现，说明严重程度、位置、触发条件、影响与修复方向。严重程度由实际后果决定，涉及其他工作包的问题交协调者处理。建议新增机制时，说明它解决的具体问题及维护代价。

返回需求符合情况和质量判断，依据可合并说明。实现满足要求时直接给出结论与关键证据；需要补充核验时说明它影响哪项判断。协调者负责安排修复和后续审查。
