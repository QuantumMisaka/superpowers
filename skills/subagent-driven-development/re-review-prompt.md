# 修复复核说明

缺陷修复后需要独立复核时，向审阅者提供以下四项材料：

```text
原任务要求：[对应的需求与完成标准]
待核对发现：[上轮审查指出的问题及依据]
实际修复：[修复前后的提交范围，或文件归属明确的工作区变更]
验证依据：[复测命令、退出码、关键输出与产物入口]
```

**复核方法**：
- 以只读方式逐条验证上轮发现是否解决，并检查修复对关联行为的连带影响。已提交变更核对完整修复范围，工作区变更覆盖暂存、未暂存与新增文件，审查期间由协调者维持工作状态稳定；需要理清调用链时查阅关联使用方。
- 复用覆盖最新行为的验证证据，针对具体疑点借助代码阅读或允许的只读检查确认；若需写入式测试或重跑构建，给出具体命令交协调者补充执行。立足原始需求与一手事实判定每条发现的状态，写清支持“已解决、继续保留或撤销”的依据。

**输出结构**：
- 按上轮待核对列表逐项回报结论、定位位置与关键证据；如发现新引入的问题，注明触发条件、实际影响与严重程度，涉及其他工作包的问题交由协调者处理。
- 结尾简明给出复核结论——修复是否满足验收要求，以及仍影响收口的剩余事项，便于协调者安排下一步。
