# Using Superpowers

选择能可靠完成目标的最轻工作流。在已确认的目标、设计和授权内，自主选择实现与工作方法；Skill 提供方法，不替代任务判断。

行动前读取本 Skill、任务适用或点名的 Skills、最近层级 `AGENTS.md` 和项目约定，简要记录 `工作流：L1/L2/L3`。已完整读取且未变的资料可复用。只读解释不启动实施流程；用户要求与适用项目约定优先。

## 路由

- L1 局部调整：目标和检查清楚，简单可逆，无实质行为或高风险外部状态变化。直接处理并做相称检查，不生成 SPEC/PLAN。
- L2 有界开发：一般功能、修复和重构，范围与验收有界。允许先查事实、澄清局部产品选择再继续；复用需求记录，不强制正式 PLAN。
- L3 计划化工作：确需统筹关联设计决策、迁移或发布顺序、跨所有者交接，或需要可恢复计划的高返工成本工作。保留 PLAN。

需要问清楚、需要设计文档、需要计划化执行分别判断。公共 API 字样、多个文件、机械迁移、一次外部审批或加载 brainstorming 本身不决定等级。
未知事实先查；普通技术选择自主决定。未定产品选择只暂停受影响部分，可用 `brainstorming` 澄清。查明后按剩余工作自然选择路径，无需降级报告。
L3 设计未定时先 `brainstorming`，已定时直接 `writing-plans`；已有设计与同范围执行授权持续有效，不因固化文档重复批准。

## 验证与执行

非平凡且根因不明的 bug 用 `systematic-debugging`。按行为与风险选择验证：可稳定自动验证的功能和 bugfix 默认用 `test-driven-development`；行为不变重构复用基线/候选检查；普通文案、格式或无独立保护价值的平凡转发采用直接检查或已有消费者测试。
原型、生成产物、缺测试设施或不可控外部依赖按实际任务选择聚焦回归、集成、替身或观测，说明影响结论的局限。缺设施不免除重要行为的验证，也不为完成流程制造无效测试。
完成声明按 `verification-before-completion` 使用当前有效证据；输入未变可复用，实际疑点才补相关检查。

已有计划的执行选择 `executing-plans`；独立工作包确有协调或上下文隔离收益时用 `subagent-driven-development`。普通 L1/L2 直接执行不因此加载计划链。
委派按任务与实际能力选择可用角色，模型/effort 归 harness 配置；具体工具操作读取当前 `references/*-tools.md`。主代理保留设计决策与最终验收责任，子代理可调查、起草和实施。
任务需要更多接地时补充相关入口、已定接口或必要例子，不因模型名称增加流程等级。独立审查按风险与项目要求选择。
普通实施取舍自主推进，重要裁决可复用计划或报告记录 `Ruling: 决定 — 理由 — 错了的代价`，不另建台账。
实质改变已批准目标、设计或授权时回到对应决策；尚缺破坏性、安全敏感或外部操作授权，或确已无可靠路径时暂停相关工作。既有同范围授权持续有效，仍遵守 harness 权限。

入口保留判据与指针，维持本人已确认的 60 行 / 6144 字节预算；适配细节与方法示例归相关技能或 reference。
