# Using Superpowers

选择能可靠完成目标的最轻工作流；依据未决判断、行为风险、协调与返工成本升级，不以文件数决定等级。

行动前读取本 Skill、命中或点名的 Skills、最近层级 `AGENTS.md` 和项目约定，记录 `工作流：L1/L2/L3`。任务意图变化时重新路由；已完整读取且内容未变的任务资料可复用。
只读解释不自动启动实施流程；点名 Skill 仍须读取。用户要求与适用项目约定优先于通用 Skill。

## 路由

- L1 局部调整：目标与检查明确，局部可逆，不改变公共行为、数据、架构或高风险外部状态。直接修改并做最小充分检查，不生成 SPEC/PLAN。
- L2 有界行为开发：目标、范围、验收与设计已明确。记录这些边界后执行，不强制完整 PLAN；bug 先查根因，行为变化按 `test-driven-development` 建立回归证据。小型兼容参数或多文件修改不自动升 L3。
- L3 计划化开发：未决产品/架构/安全决策、破坏性接口或数据迁移、跨系统协调、高风险副作用，或需要可恢复计划的高返工成本工作。保留 PLAN。

L3α 决策未定：先 `brainstorming`，用户确认实质设计后进入 `writing-plans`。
L3β 决策已定：直接 `writing-plans`，记录调查证据、用户拍板与授权来源。
已有同范围执行授权时，计划固化验收后继续，不因生成文档重复审批；设计确认不自动授权未请求的执行或外部操作。
发现级别不足时说明证据并升级。可查证的事实先查，不把未获确认的产品选择当实施细节裁决。

## 执行与分工

主代理负责设计、PLAN、验收判据与结论；子代理可收集、起草或执行，但其判断须有原始证据，主代理不得直接代批。
委派按独立性、上下文隔离和审查收益选择；按任务类型、复杂度和风险选用当前可用的预置角色，由 harness 配置提供模型、推理强度和权限；无匹配角色时按当前适配器选择默认路由或获授权的显式模型。
有意义工作包用 `subagent-driven-development`，直接执行用 `executing-plans`。
普通实施取舍自主推进，重要裁决记 `Ruling: 决定 — 理由 — 错了的代价`。
若取舍改变已批准目标、设计或授权范围，回到该决策询问用户；不可用 Ruling 扩权。
尚未授权的破坏性/安全敏感/外部副作用，或已无可靠实施路径时暂停；既有同范围授权持续有效，仍遵守 harness 权限。
独立审查按风险与项目要求安排；完成声明遵循 `verification-before-completion`，证据绑定当前工作状态，可复用输入未变的验证。
子代理不重复路由，仍读取任务适用规则。涉及子代理、模型路由或工作区操作时读取当前 harness 的 `references/*-tools.md`。

入口仅保留判据与指针；本 fork 保持 60 行 / 6144 字节预算，详细操作放入适用 Skill 或 reference。
