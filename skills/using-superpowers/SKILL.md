# Using Superpowers

核心原则：选择能够可靠完成目标的最轻工作流；依据歧义、行为风险、跨模块协调和返工成本升级。

**子代理规则：** 子代理直接执行父 Agent 给定的任务契约，无需重新做 L1/L2/L3 路由；仍读取并遵循任务明确要求或匹配的 Skills、最近层级 `AGENTS.md` 和适用项目约定。

只读提问、解释和查询直接回答；用户点名 Skill 时，先读取其当前完整版本再回答。

行动型任务的第一个流程动作是读取本 Skill 当前完整版本并记录
`工作流：L1/L2/L3`；随后读取其它命中 Skills 和最近层级的
`AGENTS.md`，再执行受管辖行动。

- L1 敏捷修改：目标和验收明确、局部可逆；不改变公共接口、数据或架构；无高风险外部副作用。由主 Agent 直接完成，不生成 spec/plan；检查局部上下文，做最小修改，运行最小充分验证。
- L2 有界行为开发：边界清楚的功能、bug 或重构。bug 先调查根因；行为变化先建立能暴露缺失行为的回归或验收证据，测试基础设施适用时用 TDD 完成 RED-GREEN；按风险选择 task review。
- L3 计划化开发：未决架构、公共 API/schema/持久化数据/架构/安全姿态变化或高风险外部副作用、多任务协调或高返工成本。

L3 内部按可观察状态选择路径：存在未决产品、架构、安全或兼容决策时先用 `brainstorming`；决策已确定但跨模块、需要检查点或高返工成本时用 `writing-plans`；已有批准计划时进入执行流程。

多文件机械迁移若需要实施分解、可恢复检查点或仓库级验证，走 L3
`writing-plans`；目标和映射已经确定时无需 `brainstorming`。

会话开始或任务意图变化时完成路由。命中或被用户点名的 Skill 在受管辖行动前读取当前完整版本。用户直接要求、最近层级的 AGENTS.md 和项目约定高于通用 Skill。调查发现当前级别不足时，说明证据并升级。

当前任务涉及子 Agent、并行工作、worktree/分支收尾或模型/Provider 路由时，读取当前 harness 对应的 `references/*-tools.md`；其它任务按需读取 reference。
