# Using Superpowers

核心原则：选择能够可靠完成目标的最轻工作流；依据歧义、行为风险、跨模块协调和返工成本升级。

**子代理规则：** 如果你是作为子代理被分派执行特定任务的，忽略本 Skill，直接执行任务。

只读提问、解释和查询直接回答；行动前仍读取命中或被用户点名的 Skill。

行动型任务的第一个流程动作是读取本 Skill 当前完整版本并记录
`工作流：L1/L2/L3`；随后读取其它命中 Skills 和最近层级的
`AGENTS.md`，再执行受管辖行动。

- L1 敏捷修改：目标和验收明确、局部可逆；不改变公共接口、数据或架构；无高风险外部副作用。检查局部上下文，最小修改，聚焦验证。
- L2 有界行为开发：边界清楚的功能、bug 或重构。bug 先调查根因；行为变化使用回归测试或 TDD；按风险选择 task review。
- L3 计划化开发：未决架构、公共 API/schema/持久化数据/架构/安全姿态变化或高风险外部副作用、多任务协调或高返工成本。进入设计澄清或 writing-plans，再按任务实施和复核。

多文件机械迁移若需要实施分解、可恢复检查点或仓库级验证，走 L3
`writing-plans`；目标和映射已经确定时无需 `brainstorming`。

会话开始或任务意图变化时完成路由。命中或被用户点名的 Skill 在受管辖行动前读取当前完整版本。用户直接要求、最近层级的 AGENTS.md 和项目约定高于通用 Skill。调查发现当前级别不足时，说明证据并升级。

`references/` 下的文件仅在当前 harness 需要工具替代时读取。
