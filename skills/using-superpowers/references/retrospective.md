# 从复盘到改进

用于用户要求的阶段复盘，或重复故障、返工所暴露的共性问题。目标是减少下一次交付的失败和等待成本；结论写入项目已有记录。

## 1. 界定问题与证据

明确时间范围、期望改善的结果和指标。调查“最慢的 PR”时，先区分交付周期、CI 耗时与代码运行性能；按问题拆分实现、审查等待、测试及外部依赖时间。结合 PR、提交、故障与回滚记录，选取典型失败和可比较的成功案例；完整扫描仅在问题需要时展开，记录覆盖范围与证据缺口。

## 2. 找到可检验的共同机制

沿事件顺序解释问题怎样发生，区分直接触发条件与共同原因。用成功案例、反例或小实验检验解释，关注哪些约束仍然存在。证据尚不足时，提出最能区分候选原因的下一项观察。

## 3. 将改进放在能解决问题的位置

优先消除实现、接口或默认行为中的成因。稳定且可判定的错误适合自动检查；项目特定约束归项目文档；跨任务反复适用、需要判断的方法归对应 Skill。复用已有入口，并合并或移除被新做法取代的约束。

例如，多次回滚都源于重试造成重复写入，优先在写入边界实现幂等并验证故障路径。若证据显示多个项目都遗漏了这一判断，再补充设计或审查方法。

## 4. 检查改进是否有效

为选定措施说明预期改善、验证方式和负责落点。当前任务内验证可观察的行为；需要持续使用才能判断的效果，在后续同类任务中比较。复盘结束时给出有证据的结论与最值得实施的改进；已授权范围内直接推进，涉及目标、架构或授权变化时沿用入口的双相协作契约。
