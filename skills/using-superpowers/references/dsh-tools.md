# dsh / ds-bot 原生协作适配

适用于 dsh Web 的 ds-bot 团队。2026-10-18 核对 dsh 0.2.1-rc.2、ds-bot 0.1.6；升级后以实际工具 schema 为准。CLI 单次任务不假定拥有这些团队工具。

## 入口与职责

Main Bot 读取 using-superpowers，承担任务分级、目标与依赖管理、派发和最终验收。L1/L2/L3、设计、实现和验证沿用共享技能，不另设流程。简单任务由 Main 直接完成；有独立工作包时按需使用专业成员。

专业 Bot 按委派范围读取项目规则、对应角色技能及必要专业技能，不重复主代理入口路由。主代理给出任务、文件归属、相关接口、验收依据和返回要求；成员报告实际证据与需要主代理决定的问题。稳定职责与关键边界写入 Bot instructions，详细方法引用技能，临时任务通过消息交付。

先 list_bots 再选择成员。复用上下文相关的 Bot；无关任务或需要独立判断时考虑新建。创建前读取适用角色技能，将关键职责写入 instructions，brief 说明本次目的。原生 create_bot 仅 Main 可用；其他成员需要新岗位时向 Main 提出。不要把角色技能名当成已注册的 Bot 或模型。

## 与 L1/L2/L3 联动的默认路由

等级定义仅使用 using-superpowers，不因模型、Bot数量或群聊升级等级。Main先分级，再挑选实际需要的工作阶段；开工用一句话说明级别、复用的依据和拟派角色，无需再次索要同范围授权。

| 等级 | 默认执行 | GPT及独立成员 |
|---|---|---|
| L1 | Main直接完成相称检查，不建SPEC/PLAN或固定团队 | 仅项目明确要求、用户指定或具体风险需要独立判断时派发 |
| L2 | 复用有效需求/方案；DeepSeek直接或按有界工作包实现和验证 | 重要事实/方案不确定时优先GPT调查；满足requesting-code-review的条件时优先GPT审查；其余按项目要求与风险处理 |
| L3 | 保留项目PLAN，Main管理依赖/交接，独立成员执行有意义的任务包 | 默认优先GPT承担缺失的调研/规划与最终审查，已有有效成果核对后复用，不自动重跑七阶段 |

本人已授权此dsh默认路由在适用任务中使用现有GPT执行器。角色/模型/effort仍以当前目录及实际工具为准；GPT路由不可用应说明受影响阶段，不能把DeepSeek输出冒称GPT，不能仅为赶进度绕过必要审查。跨模型偏好只属于此适配，不改变Codex等其他入口配置。

调研解决具体未知项；方案复核重点是“依据这些输入能否开工、还有哪些真实缺口”。沿用 brainstorming 的按需可开工检查：普通实现选择自主决定，有关键新决策才回用户。仅有需要修订的内容时才派文档完善员；不创建没有独立产出的岗位。

每个选中的独立专业阶段使用新的聚焦会话/任务，给出必要事实、文件归属和验收依据，避免完整主会话复制。修复轮可续用原实现者，独立复验保持独立。多个无依赖工作包可以并行，依赖阶段待实际结果后再派发；这一规则不要求把每个小操作拆成一个Bot。

微型任务调查/计划只需短结论；Main在任务说明中给出相称篇幅与停止条件，达到验收即交接。L2通常复用需求记录，L3复用项目计划；不要为角色数量配套造文档。项目规则、已确认决定与实际证据优先，个人品味只在相关取舍或表达中读取。

用户明确要求完整七阶段时，按[跨模型阶段编排](dsh-cross-model.md)执行；默认路由也可从其中选取所需阶段，省略的阶段标明复用/无需，不声称执行过。

调用外部角色时使用已挂载能力的工具与角色目录，按已知 `workspace_name=team` 工作。工具受阻时报告缺口；不探查其他home、任务私有输入或凭据来拼接调用。原生workspace-write通常不限制读取范围，聚焦输入需要遵守这条职责边界。

## 工具映射

| 动作 | 原生方式及语义 |
|---|---|
| 发现成员与群聊 | list_bots；成员名单可能变化，不凭记忆猜名字 |
| 创建/调整成员 | create_bot / update_bot；尊重用户已有设置和原生权限 |
| 独立派发与继续 | message_bot，默认 reply_to=me；消息必须自包含，目标看不到发送方对话 |
| 当前私聊任务纠偏 | message_bot 默认 when=now；目标在下一步读取 |
| 无关的新任务 | message_bot when=queue，避免打断现有私聊任务 |
| 结果回收 | 异步回复触发后续处理；有独立工作就继续，无事可做就结束本轮等待回复，不轮询、不重发，不虚构 wait_agent |
| 用户直接听成员汇报 | reply_to=user；结果在成员私聊显示，不会回给派发者 |
| 事项讨论 | create_group / update_group / post_to_group；用精确成员名 @ 调度 |
| 紧急停止 | Main 使用 stop_bot；会影响目标运行任务与队列，不作为日常等待手段 |
| 计划与进度 | 项目已有计划/交接文档；ds-bot 隐藏 DSH goal 工具，不虚构 goal 生命周期 |

模型从当前可用目录选择，默认沿用原生配置。create_bot / update_bot 的模型工具参数不含 effort 和 permission；需要这些设置时走原生 UI 或已授权配置接口，并验证实际值。角色正文的“只读”是职责约定，不能替代权限。可选外部 CLI 执行器只在任务需要且已授权时使用。

## Main 主持群聊

默认 Main 担任 admin、mode=admin：用户普通消息先交主持人，由其定向 @成员。@ 是调度动作；只叙述某成员时写名字，不加 @。@all 用于确需全员输入的事项。无新增信息或非本人的问题按原生规则返回 [PASS]，不互发致谢与状态回声。

每个事项群明确目标、共同依据、分工和收敛条件，写入 notice；项目规则仍适用。主持人派发、接回结果、处理分歧并验收，不要求每位成员轮流表态。成员被要求执行时实际完成工作，关键进展和结果在群中报告，不只承诺稍后处理。

选择主要执行会话：独立调查/实现/审查通常私信派发；需要用户可见进展或共享讨论的任务在群中派发。message_bot 只进入目标私聊，不会传到它正在执行的群会话；群任务在对应群内纠偏。Main 从自己的私聊 post_to_group 发起讨论时应显式 @目标成员：发送者不会回答自己的帖子，不能依赖 admin 自动接管自己发的无 @ 消息。需要结果异步回到发起者时设置 report_back=true；默认只在群内显示，后续可用 read_group_chat 查看。群轮次结束不代表所有长任务已完成：report_back 可能仅回传进展和 Still working，晚到结果留在群内，由群中指派者接回；需要私聊最终汇总时再 read_group_chat 读取实际完成结果，不能把进展回传当作完成。

同时 @ 多名成员适合独立输入；长任务可能仍在运行时轮次就推进，不能靠 @ 顺序保证依赖。若 B 必须基于 A 的结果判断，先只 @A，待实际结果到达后再 @B 并附上结果。独立任务先各自形成结果，再将必要证据带入群中讨论分歧。讨论收敛后 Main 把决定、未决项和下一步写回项目文件，按 verification-before-completion 核验后报告；群发言或成员自报成功本身不等于验收通过。原生轮次和消息链有上限，遇到限制先汇总状态，不靠重复发送绕过。

## 信息聚焦与隔离边界

Bot 私聊独立；每个 Bot 在每个群也有自己的会话，但沿用该 Bot 的身份设定。首次群会话会带入该 Bot 私聊最近最多 10 条消息摘录；可用 read_own_chat 回查私聊，read_group_chat 回查可见群聊。新群不等于全新干净上下文。

另有 Bot 自有记忆、团队共享记忆和共同文件。需要独立审查时给出需求、实际变更及证据，避免预灌实现者结论；必要时新建审查 Bot。新 Bot 仍可能读取团队记忆与文件，不宣称严格盲审或安全隔离。严格隔离需求应使用明确的数据/权限边界另行实现。

并行写入明确文件归属，重叠写入串行或隔离工作区；会话分开不隔离 Git index 或项目文件。群权限可覆盖成员个人权限，审查者进群后不能只凭其个人设置声称只读。

项目文件保存目标、计划、决定和验收事实。个人品味按架构取舍、协作或表达需要读取相关部分；稳定且跨任务有用的事实才适合团队记忆，临时假设保留在事项中。

## 来源与维护

工具语义核对安装包 ds-bot 的 src/host/{tools,groups,prompt,permissions,chat-index}.js；技能发现核对 @deepseek-ai/dsh-skill-filesystem。此说明随 Superpowers fork 同步，以项目挂载的固定版本消费，不在每个 home 复制另一份规则。发现同名技能覆盖时核对实际解析路径。

用户指定 GPT调研/规划→DeepSeek实施→GPT验收时，使用[跨模型阶段编排](dsh-cross-model.md)；该模式按阶段新建执行会话，普通任务保持上述按需协作。
