# dsh 跨模型阶段编排

触发：用户明确选择完整 GPT 调研/规划 → DeepSeek 复核/完善/开发/测试 → GPT 验收，或 Main 按 dsh-tools.md 的 L1/L2/L3 默认路由选择其中必要阶段。完整模式执行下表七阶段；按需模式复用有效成果、只执行必要阶段。Main按using-superpowers分级，不因跨模型或多成员升级等级。

## 阶段与独立执行者

| 阶段 | 执行者 | 交付 |
|---|---|---|
| 1 调研 | 新 GPT context-analyst 外部任务 | 事实、引用/路径、约束、未知项 |
| 2 规划 | 新 GPT context-analyst 外部任务 | 基于事实的方案、依赖、实施步骤、验收标准；只读返回提案，不授权设计变更 |
| 3 复核 | 新 DeepSeek context-analyst Bot | 对项目实际与调研/计划逐项核对，记录成立/不成立/待核实 |
| 4 完善 | 新 DeepSeek document-writer Bot | 修订计划、边界、任务包和验收依据；关键新决策交用户确认 |
| 5 开发 | 新 DeepSeek standard-worker 或 routine-worker Bot | 明确归属的代码和实现自测 |
| 6 测试 | 新 DeepSeek 验证 Bot，采用 task-reviewer 只读职责 | 独立运行测试、复现/边界证据；若需写独立测试，另设明确写范围的 routine-worker 职责 |
| 7 验收 | 新 GPT final-reviewer 外部任务 | 对需求、决定、实际变更、原始验证证据独立审查，给结论与可操作发现 |

规划复用 context-analyst 的只读分析契约：任务限定为分析候选与建议步骤，主代理保存其返回文本；不把它称为已注册 planner。模型/effort/权限由当前角色目录决定，先 list_roles 验证，不能靠文档中的模型名覆盖路由。

## Main 的执行协议

1. 确认项目与本轮目标，在项目适合的位置记录阶段状态、输入/输出路径、Bot ID或job_id及必要验证命令；复用现有计划/交接，不额外制造台账。
2. 只给Main挂载已批准的 team-role-executor。现有能力缺失时报告具体缺口，不自行安装新后端。GPT阶段通过该MCP的 start_role(family=gpt, role=..., workspace_name=team, task=...)；每次新job，不resume，不由Main模拟结果。参数已由当前能力契约与list_roles提供，不通过其他home、role-jobs/input.json、Bot运行态或凭据反查；工具不可调用时报告具体缺口，不用bash绕过执行器。
3. 外部任务保存job_id。装有完成通知插件的Web会把终态通知投递给实际发起Bot的私聊，并唤醒它调用 role_status 读取结果；群内发起仍回到该Bot私聊，通知注明来源群。通知不携带结果全文。按job_id去重，已处理的通知不能重复启动后续阶段。通知绑定持久化后可跨Web重启恢复；投递与确认间崩溃可能重复通知，任务启动与绑定间崩溃可能漏通知。旧Web、绑定失败或长时间未收到通知时，可使用有间隔的有限 role_status 查询（如15秒）恢复，不重新start_role、不紧密轮询。服务超时默认300秒；失败/超时/结果截断必须明示，只重做受影响阶段，不把失败替换成Main自己完成。长任务先拆分；增加宿主超时需配置并验证。
4. DeepSeek每个选中的独立阶段创建新的Bot，身份设定包含职责、当前项目、输出边界、不得重复主入口路由。即便已有同岗位成员，本模式也不复用旧执行会话。每个阶段只派发一次，等待真实完成后校验产物再进入依赖阶段；结果只回Main，避免同一事项同时在群与私聊执行。
5. 任务说明包含目标、限定输入、负责文件、已确认决定、验收标准和返回格式。Main按任务规模给出产物长度和调查停止条件；微型任务的调研/计划/复核各用简短结论，计划通常一两页足够，不因七阶段而扩写治理、重复探测标准库或枚举未来需求。已有事实只在证据冲突时复验；达到阶段验收即交接。前阶段结果连同必要源证据交给后阶段，避免复制主会话全文。Main可保存GPT原始返回并作标明来源的摘要，不能改写后冒称GPT原文。
6. 独立测试/最终审查读取需求、实际代码/变更和证据；不要只传“已通过”结论。不提供实现者的自我评价作为验收依据。审查中的真实失败回到新建或明确继续的修复任务，之后重新独立验证；记录这属于修复轮而非首轮通过。
7. 有争议时才使用事项群，Main任admin，先独立判断再讨论。依赖任务分轮@；GPT是外部执行结果，应标注来源，不能创建DeepSeek壳Bot并声称它是GPT。Main负责核验、收口和项目交接，不能把GPT结论直接当最终事实或用户批准。

## 隔离与权限

GPT执行器每次 codex exec --ephemeral 新会话；DeepSeek每阶段新Bot。两者均可能读取项目规则、共享文件，DeepSeek还可能消费团队记忆。这里保证任务会话分开与输入聚焦，不承诺严格盲审或安全隔离。限制团队记忆中的临时结论；角色边界不能替代真实权限。只读验证Bot需核对原生权限，若无法设置应明确实际权限，不能声称已是只读沙箱。并行写操作按 dsh-tools.md 的文件归属纪律处理。

最终汇报分别列出各阶段是否真实执行、使用的路由/身份、产物和证据、失败或待决项。只有所有必要阶段完成且问题关闭，才报告跨模型链路完成。
