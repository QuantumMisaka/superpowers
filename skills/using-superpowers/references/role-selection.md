# 按所需成果选择角色

L1/L2/L3 决定工作的组织方式，角色承接具体成果。主代理负责理解用户、确定范围、收束决定与整合交付；委派是否有益，取决于工作能否独立交付及其协调成本。

| 所需成果 | 角色 | 派发时说清 |
| --- | --- | --- |
| 发现可推动项目的能力与工作机会 | `capability-advisor` | 项目目标、当前状态、已有任务与本次可用能力 |
| 查清事实、根因或设计历史 | `context-analyst` | 要回答的问题、相关来源与证据范围 |
| 比较候选方案并给出推荐 | `design-analyst` | 期望结果、实际约束、已有决定及关键取舍 |
| 完成局部实现或行为复现 | `routine-worker` | 目标行为、可改文件与检查方式 |
| 完成跨文件实现或集成修复 | `standard-worker` | 接口、相关使用方、写集与完成标准 |
| 核验工作包或整体交付 | `task-reviewer` / `final-reviewer` | 实际变更、验收目标、已有证据及疑点 |
| 形成文稿或审阅表达 | `document-writer` / `document-reviewer` | 主读者、文档用途、来源与已定取舍 |
| 分析科学证据或撰写论文 | `paper-analyst` / `paper-writer` | 研究问题、主张、证据及体裁 |
| 判断是否达成目标、下一步做什么 | `progress-reviewer` | 当前目标、产物与完成标准 |
| 跟踪长任务与关键日志 | `monitor` | 运行身份、观察入口及需报告的事件 |

## 能力发现与提醒

用户询问还能让 Agent 做什么，或需要在项目新阶段选择投入方向时，主代理可委派 capability-advisor。它根据项目依据推荐少量具体工作，说明适用角色、预期产物与最小启动范围，并核对已有任务和能力可用性。主代理收束本轮范围并组织执行；明确的局部任务直接走对应角色。提醒由当前对话中的主代理触发。

## 按场景组合

- **故障修复**：原因不明时调查，定位后实现；紧耦合的问题可由一个 worker 连续完成。
- **方案设计**：主代理结合用户偏好澄清目标；需要独立比较时委派 design-analyst。方案形成后，重要判断可另交 reviewer 检验。
- **历史包袱与接手成本**：context-analyst 查动机与当前使用方；需要提出结构调整时由 design-analyst 比较方案，再交 worker 实现。
- **瓶颈与阶段复盘**：先明确指标和范围，由 context-analyst 关联事件与证据；涉及改进方案时使用 design-analyst，当前任务是否收口交 progress-reviewer。方法见[复盘指南](retrospective.md)。

例如，缓存方案尚未确定时，让 context-analyst 查明耗时分布，让 design-analyst 根据测量比较缓存、批处理或队列调整。只有调查结果足以支撑比较后才进入方案分析；小问题可由主代理一次完成。

每次派发给出问题、预期成果、已有依据和读写范围。普通实现沿用已定设计；新发现会改变目标或关键取舍时，由主代理按双相协作契约处理。角色名与权限以当前 harness 实际注册为准，适配器负责解析具体名称。
