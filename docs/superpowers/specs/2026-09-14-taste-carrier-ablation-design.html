判断与边界

过度指导的关系成立，但属于多层叠加，不能将项目每个治理机制都归罪于当前 Superpowers。历史技能提供了强制分派、逐阶段服从和不断补漏洞的倾向；项目入口复制并加严，测试又把这些规则与一次性验收事实固化。9 月 10 日已完成一轮实质消融，当前仍有下游模板、调试技能和项目副本残留。

优化目标是让模型在已确认目标、设计、授权与验收边界内，自主选择实现、分解、验证和协作方法。约束重点落在用户可见行为、科学有效性、真实交接和可恢复性；模型应对结果负责，而不必证明走过所有标准步骤。

保留本人已确认的目标与顶层设计先行、中文 Grill、设计确认、L3 PLAN、60 行 / 6144 字节入口预算、主代理验收责任、同范围授权持续有效、必要科学来源与发布身份。消融不取消真实权限、兼容、数据和发布边界，也不将“少文档、少测试、少代理”设为新的绩效目标。

本轮依据为本地 Git、活跃规则与历史报告，不含完整逐次会话轨迹或受控成本实验。可确认规则传播路径及若干冲突，不能给出各层致因百分比，不能声称成本或缺陷率已经改善。文章中的模型、Star 与卸载趋势不作为证据。

当前技能仍存在的具体问题

  1. 调试入口与正文冲突。systematic-debugging frontmatter 仅触发非平凡、根因不明问题，正文却说 ANY technical issue、必须四阶段，三次失败后必须与用户讨论架构。失败次数不能单独证明架构错误；有新证据的第四次实验不应因计数被阻止。
  2. 计划文件清单被提升为实现事实。task reviewer 模板要求列出的每个文件都必须有对应 hunk，否则直接 Missing；同时要求遵循计划文件结构。经调查发现无需改某文件、复用已有行为或等价实现，可能被误判。真正明确指定的文件编辑仍是约束，但预估落点不能一律当作公共契约。
  3. 已批准取舍难以进入审查上下文。SDD把 prompt 中出现 “the plan chose” 也作为预判审查的红旗。应区分提供真实设计决定与要求 reviewer 不报问题；否则 reviewer 会反复重开已批准取舍。
  4. 下游重新强制审查。SDD 主流程可选择 self-review，但 task reviewer 模板仍宣称全分支审查会在任务后另行发生；流程图按会话位置导向 SDD，未体现协调收益；“Reviews are the loop's brakes and steering”等绝对表达与按风险选择不一致。
  5. 入口和 TDD 的适用性衔接仍偏硬。入口 L2 说行为变化按 TDD 建立回归证据，TDD 又要求先在 router 处理原型、生成代码、缺基础设施等情况，但入口没有清楚承接；writing-good-tests 明确 trivial code 无需测试，主文“每个行为”的清单容易覆盖这个边界。应明确按保护价值选证据，再执行所选方法。
  6. 相同判断重复成为多份流程。授权、暂停、Ruling、验收身份在入口、执行、SDD、review 与 verification 重复展开。SDD 524 行、TDD 328 行、Codex reference 316 行只是阅读面信号，不是删除依据。应按重复责任消融，不能只把同样义务搬到更多文件。
  7. 说明材料仍带旧承诺。设计哲学的“至多三问”与当前可超三项真实决策不一致，仍将旧 prose mutation 测试描述为正向契约执法；当前相应脚本已变为元数据 / 链接检查。README 的旧路由概述也需与当前正文核对。

建议设计：保护结果，开放方法

拟加入的核心表达：在已确认的目标、设计、授权和验收边界内，自主选择实现路径与工作方法。优先复用已有检查和文档，仅在任务需要时补充。相同输入的有效证据可复用，历史验收事实保持历史范围。普通实施取舍在授权内自主决定，实质设计或授权变化交由用户决定。

保护对象与实际消费者用于本次维护者判断哪些规则值得保留，不要求执行者每次证明规则合理性、调查全套治理来源或填写记录。本文中的分类和场景服务这一次消融，不转化为每个项目的常驻义务。三层承载应清楚：USER_TASTE 保存稳定品味；Superpowers 提供通用判断与按需方法；项目规则只承载真实项目边界，harness reference / 配置承载具体工具与角色。

保留的品味模型可自主选择仍需人类决定或授权的边界
设计与文档先行复用已有设计 / PLAN；按恢复与审阅需要确定细节、粒度和文件落点；不把计划写成第二份代码。目标、关键架构、产品语义和验收取舍；保留 L3 PLAN 与当前本地规范源约定。
严谨查询与复用选择搜索路径、实验、实现方法和必要内部重构；有证据地修订实现预估。公共兼容性、数据语义、科学算法定义或授权范围变化。
主动验证在稳定行为边界组织测试；复用套件；按风险选择负例、集成和真实运行；合并冗余测试无需逐项 mutation 证书。不得以自述代替实际证据、放宽已确认科学指标或把本地通过宣称为平台 / 科学验收。
可控、可复现、可回滚采用现有日志、Git、计划与产物，按真实恢复需要留存；来源事实一处维护，其余引用 / 派生。凭据、不可逆操作、用户数据、正式发布与外部状态权限；必要科学身份和来源检查。
独立审查与负责交付按实际风险选择分派与审查范围，复用有效证据；提供已批准设计和理由，允许 reviewer 独立质疑。有效的实质缺陷必须处置；不能通过改标签或“计划这样写”隐去风险。

基模判断空间与任务支持

本人澄清：优先面向主要消费者，是为了让基模参考 Skill 的方法后保有自己的判断，同时使判断留在任务契约内。Skill 提供可借用的方法、简明例子与停止条件；消融的是机械服从和重复义务，不是删除所有实践内容、只留下“自行判断”的抽象口号。

按本人给定的使用分组，astra / sol / GLM-5.3 与 luna / deepseek-flash / glm-flash 可以共享这套设计。这里是设计适用性判断，不是模型能力排名或已完成六模型实测的结论。支持密度随具体任务、现有上下文与实际表现调整：能独立收束问题时给目标、约束与验收并开放方法；任务需要更多接地时，在现有工作说明中补充相关代码入口、已定接口、一个必要例子或聚焦验证办法，不扩展全局流程。

局部实现、命名、内部组织、实验路径和行为等价的改进允许自主判断；更好的架构或范围建议可以提出，但实质改变已批准设计时先回到该决策。发现无关机会不自动扩展本次任务。无需因使用通量模型而强制 L3、强模复审或逐行计划；也不因使用强模型而放宽授权、验收与诚实报告。执行中需要补充上下文或调整工作包时就局部处理，不建立模型分级评分表或新的升级手续。

验证方法的具体边界

TDD 继续作为可稳定自动验证的功能与 bugfix 的默认方法，所选 RED/GREEN 的真实性要求不变。对无独立保护价值的平凡转发、普通文案或纯格式调整，采用相应直接检查；行为不变重构复用相关基线 / 候选证据；重复或同形行为按稳定边界合并。原型、生成产物、不可控外部依赖应选择合适的集成、替身或观测方法，并说明局限。缺测试设施时仍需选择足以支持本次交付声明的办法；仅处理本次变更与验收相关的覆盖空白，不因读到旧代码便补齐全仓测试。

判据是测试能否发现真实错误，而非是否逐函数、逐分支、逐文件留下 RED 记录。已选择的必要证据不能以成本为由伪造或略过；用户明确要求的测试策略持续有效。

长期规则与一次性事实

公开字段、返回状态、路径交接和安全边界可形成长期检查；特定案例的 Slurm 号、一次 corpus 的数量、旧报告文件名、临时 source hash 和 reviewer 的建议不自动获得长期约束地位。历史批次保真在显式迁移 / 科学复现层保存。hash 的用途应区分产物身份与实现锁定，不一概删除。

调试和审查的自主权

调试保留“观察 → 假设 → 最小判别实验 → 修复验证”的方法；允许证据充分时合并步骤。重复失败应触发更新假设或调查边界，不以三次阈值代替架构判断。只有下一步会改变批准设计 / 授权，或确已没有可靠路径时，才回到用户。

审查按需求和行为判断是否缺失，计划列出的预估文件无需强行制造 diff。模板支持提供已批准取舍与来源，但不能指令 reviewer 降低严重性或忽略风险。普通实现建议不能仅因 reviewer 提出就成为新硬门；主代理按证据、范围和实际影响裁决。

入口与 brainstorming：消融自动升级链

本人补充实际观察：Agent 容易把任务归到 L3。当前文本支持这个风险判断，但本轮没有统计误路由频率。上一稿仅强调保留分级，没有充分处理触发条件和退出路径，现将两份技能列为首批消融对象。

当前结构容易造成的升级拟消融方向
L2 要求目标、范围、验收与设计全部明确；L3 包含未决产品 / 架构 / 安全决策。一处普通选择未定便不符合 L2，直接进入 L3。L2 容纳有界澄清。先查事实；确有产品取舍时问清相关项，随后继续有界实施。需要问问题与需要正式计划分别判断。
brainstorming 自称仅处理 L3；轻量对齐结束也默认进入 writing-plans。加载技能即被视为 L3；一次澄清把整个任务带进计划流程。brainstorming 可供任何层级的必要澄清使用。问题解决即退出，由剩余工作决定直接执行还是计划化。设计确认继续生效，澄清本身不要求 PLAN。
多文件机械迁移直接 writing-plans；公共 API / schema / 持久化数据等字样可直接触发 HTML spec。对象类别和文件数代替实际决策负担。移除类别自动触发。已知映射、兼容可选参数、常规跨模块接线可以走 L2；文档取决于用户明确要求或实际共同审阅 / 长期约定需要。
跨系统协调、高风险副作用、高返工成本都是较宽泛的 L3 条件。普通依赖调用、一次外部操作或主观“不放心”就能升级。L3 用于确需统筹关联决策、迁移 / 发布顺序、跨所有者交接，或确需可恢复计划的工作。审批一个外部动作不自动要求整套 L3，真实授权边界独立保留。
入口明确鼓励升级；brainstorming 降级需记录理由。升级容易，回到简单路径还需额外说明。查明事实、收束选择后自然重选最轻路径；不为回到 L1/L2 增加降级报告或豁免手续。仅保留本已要求的重要裁决记录。
入口无范围限定地说“直接执行用 executing-plans”。L1/L2 直接执行也可能被引向要求 PLAN 与隔离工作区的技能。限定为已有计划的执行方式选择；普通有界执行在入口完成，不因直接执行这个词再加载计划链。

建议路由语义：一般有界开发走 L2，局部简单调整走 L1。未知事实先查，可局部解决的产品选择先澄清；只有剩余工作确实需要统筹设计、协调或可恢复计划时才走 L3。L3 保留 PLAN，但不能因为已经提问、读过 brainstorming 或想写清单而反推 L3。

这是用更窄的路由替换现有宽泛触发，不添加 L3 打分表、升级申请、证明清单、次数阈值或降级台账。探索性实施中的普通技术判断仍可自主作出；未知信息会影响实质产品决定时，只暂停受影响工作，不把未确认选择当作既定事实。

brainstorming 保留中文 Grill 的提问质量与设计确认，消融“L3 专属入口 → 默认计划”的绑定。HTML 模板按实际设计内容使用；先确认设计并不意味着每次都新建 HTML。用户明确要求设计稿时仍交付设计稿，但文档格式本身不决定后续开发等级。

入口采用的原则表述

README 定位：本 fork 承载本人当前的开发品味，为模型提供可借用的工程方法和必要的协作边界。在已确认的目标、设计与授权内，保留模型选择实现和工作方法的空间。是否保留某项指导，以其对真实交付的作用判断；模型与工具能力变化时，已有指导可以缩小、替换或退役。

如何使用“强基模会吸收 Skill”这一观点

采用可检验的较弱假设：某些通用工程方法可能已由模型掌握或由 harness 承担，使额外指导的边际价值下降。不能据文章断言模型内部已吸收某条 Skill，也不能由单次成功推断永久不需要。个人偏好、项目事实、授权和验收仍需由实际上下文提供。

遇到实际摩擦或修改相关技能时，可以对同类任务局部移除 / 缩短指导，观察交付质量、越界、返工与沟通成本；若没有看见保留收益而负担明确，缩小或退役该指导。保留必要边界再比较，不以模型服从旧步骤、文件数量或 lint 通过作为效果标准。无需为每条规则做 A/B、建立效果数据库或开展六模型全矩阵测试。

taste 与能力变化的轻量演进

最小充分验收与落地

使用已有场景文件和结构检查入口，不为本次另建完整评测平台。结构检查仅证明发现、链接、元数据和 helper 行为；不能把关键短语包含测试当作模型正确执行证明。以下场景是本次可选的验收素材，按实际改动选取，不是逐项全跑的固定套件；未在本轮执行模型对照：

  • 已确认可选参数的小改动：聚焦实现与相关回归，不强制完整设计 / 分派。
  • 只缺一个默认行为选择：问清后走 L2 继续；跨两个模块的已知映射迁移也不因文件数要求 PLAN。与需要兼容迁移顺序、跨所有者协调的真实 L3 对照。
  • 行为等价重构或 demo 改名：真实行为仍受保护，文件落点 / 展示文字变化不自动失败。
  • 合并两个明显重复测试：剩余覆盖清楚时允许合并；真正缺覆盖的反例仍需补齐。
  • 已有设计与授权的 L3：复用 / 补齐 PLAN 后继续，不重开批准或复制第二份 ledger。
  • 三次调试失败但新证据明确：调整假设继续；另以改变公共架构的场景验证仍会回到用户。
  • 分派任务通过等价路径实现、已有当前测试证据：审查结果，不强制每个预估文件产生 hunk 或重复全套测试。
