# Superpowers 的历史取舍与下一轮消融

2026-11-18。读者：维护者。审查意见，不新增 Agent 运行规则。

## 结论与基线

这套 fork 最值得保留的不是完整开发流程，而是三项通用模型不能替你决定的事情：哪些取舍由你拍板、哪些证据足以交付、任务在什么条件下值得隔离或委派。下一轮优先修正会让同一任务走出两种相反行为的措辞；冷资料的行数排在后面。

审查开始时，独立检出位于 `2a2018b`，维护者的技能挂载与父仓 gitlink 位于 `fa668e3`。下文的统计和问题定位以 `fa668e3` 为审查快照。该提交可达 777 个提交，比独立检出多 32 个（第一父链 29 个）。GitHub 对 `QuantumMisaka/superpowers` 的 all-state PR 查询返回 0；所以用**上游 PR**还原共同起源，用**本 fork 提交、设计与消费端**判断个人决定，不把 release PR 当个人设计理由。没有将提交遍历等同于逐条复验当年的模型表现。

## 当前可删、可改与不可删

**最该先处理的反例：一次精简删掉了仍有用的安全条件。** `6f354e7` 明确处理 detached worktree 的同名恢复引用；`d35df2b` 精简后仍要求确认归属，`aaebe0c` 后，现行 `skills/using-git-worktrees/SKILL.md:21,41` 的示例直接 `update-ref`，不校验旧值。同名时可能移动另一任务的恢复指针。第 48 行还让创建失败后一律退回当前检出，未区分“隔离只是方便”和“有并发写入、必须隔离”。应恢复这两个条件，不恢复旧版整章：不占用归属不明的引用；仍需隔离时只继续不冲突的工作。验收用两个同名任务和一个创建受阻的共享写集，而非断言某句警告存在。此处是静态识别的风险，并非观察到用户数据已经丢失。

同处还有一个反方向的问题。在现行源运行 `bash tests/claude-code/test-worktree-path-policy.sh` 返回 1，九项中两项要求旧英文目录措辞，而现行说明仍给出 `.worktrees/<name>` 默认路径，清理资格也不由目录名决定。测试来自上游 #1476（`d00f4ad`）禁止旧全局回退的工作。应退役锁措辞和锁历史文档的断言，保留默认路径、归属与安全清理的语义；把旧句补回正文只会让 Agent 多读字，却不会发现前述引用风险。

## 怎样聚焦实际工作

14 个 `SKILL.md` 从 9 月检出的 1,486 行 / 71,773 字节变为现行 549 行 / 41,768 字节，正文总字节已减少 41.8%。与此同时，入口从 3,569 增至 3,917 字节。总量是库存，不是一次调用实际读取的上下文；没有同任务对照，不能推出效果提升或下降。README、历史设计、按需 reference、插件脚本也不能算进每次任务的提示词。

| 你的实际任务 | 最短有效路径 | 不该丢掉的分岔 |
|---|---|---|
| 修一个已定位的解析错误、修改科学计算工具配置 | 查调用方和实际输入，直接修，在失败边界验证。 | 配置改变资源选择时看实际选择；真实作业运行未验证就不要宣称已完成平台验收。 |
| 调查跨主机或平台故障 | 症状、可区分的原因、最小观测，再决定修复。 | 未知事实自主查；要改变数据语义、产品取舍或外部授权时，只问受影响的问题。 |
| 设计跨模块接口或迁移，分给多个实现者 | 必要时由 Markdown 设计与计划固定接口、顺序、验收；按可独立成果派发。 | 共享工作树或生成产物不能仅凭“两个任务”并行；需要恢复和交接时保留工作包证据。 |
| 科研、论文、超算、平台交付 | Superpowers 只决定如何组织工作，科学判据、作业参数、交付格式由项目或领域 Skill 提供。 | 不把通用示例升级为科学验收；不把专业规则反向复制进入通用入口。 |

建议下一次只在真正消费的版本动手：先修 worktree 两条安全边界并清理误导性测试，再把验证按行为分流、让角色选择回归一个来源。复用一次普通维护和一次需要协作的真实任务，观察是否少一次无价值加载、避免一次错误验证、仍能识别需要人拍板的决定。没有发现摩擦的冷资料不急着处理，也不新建周期审计、字数阈值或全模型矩阵。
